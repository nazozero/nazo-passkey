# Fuzzing

Run `cargo +nightly fuzz run ceremonies -- -max_total_time=120 -rss_limit_mb=1024`.

The checked-in corpus contains unmodified W3C §16 public test bytes and
boundary cases. `python3 fuzz/seed_corpus.py` regenerates the 45 named W3C
seeds using the existing `tests/fixtures/w3c-level3.json`; no dependency
installation is required and no signatures are generated by that script.

The first input byte selects both the fixture and the entry point:

- Fixture: `(selector / 8) % 5`, in the order none ES256, packed self ES256,
  packed ES256, packed Ed25519 credential, FIDO U2F ES256.
- Mode: `selector % 8`, as listed below.

| Mode | Mutated input | Valid input retained around it |
|---|---|---|
| 0 | Registration attestation CBOR | Matching credential ID, client data and challenge |
| 1 | Registration clientDataJSON | Matching attestation and registration state |
| 2 | Assertion authenticatorData | Correct stored key, ID, client data and signature |
| 3 | Stored COSE public key | Correct assertion and account binding |
| 4 | Assertion signature | Correct key, authenticatorData and client data |
| 5 | External response JSON | Correct ceremony state; seeds include registration and assertion bodies |
| 6 | Authentication clientDataJSON | Correct authenticatorData, key, signature and state |
| 7 | Discoverable user handle | Correct empty allowCredentials state, assertion and independently selected account handle |

Every fixture must pass registration, real assertion signature verification,
and the discoverable entry point when the harness initializes. Each seed is
paired with its own fixture: a packed certificate seed must not stop at an
unrelated credential-ID mismatch. Both ES256 and Ed25519 verification paths
are reachable with valid seeds. Creation timestamps are refreshed on every
iteration so longer runs cannot silently stop exercising parsers after TTL
expiration. No validation or account binding is disabled to gain coverage.

The property tests in `src/cbor.rs`, `src/cose.rs` and `src/auth_data.rs` run
with `cargo test`. Fuzzing is an additional bounded experiment, not a proof of
parser correctness. Keep minimized regression cases when a failure is found.
